# OpenGal 记忆方案：「三簿一窗」架构

> 版本：v2（2026-08-26 重写，替代初版"三层事实库"拼装方案）
> 定位：为 OpenGal（galgame 式 Live2D 单用户桌面伴侣）设计的**原生**记忆架构。
> 原则：学友商的教训，不复刻友商的工程。

---

## 0. 为什么叫"三簿一窗"

galgame 角色的记忆不是数据库，是她自己的"三本簿子"加一扇"回想之窗"：

```
流水簿（已有）── 她经历的一切原文          ─┐
心记簿          ── 她记住的关于你的事实      ├─ 落在 data/memory/<角色>/ 下
物语簿          ── 她记住的你们的故事        ─┘
                                                    ↓ 每轮装配
回想窗          ── 她此刻"想得起来"的东西 = 角色卡 + 记忆块 + 近窗对话
```

**记忆的单位是叙事，不是三元组。** 一个人记得"考试挂科那晚她陪我聊到十二点"，而不是记得 `(用户, 经历过, 考试挂科)`。这是本方案与所有参考项目的根本分歧：友商把记忆当知识库管理（事实/图/向量），OpenGal 把记忆当角色的生命经历管理（簿子）。

---

## 1. 三条铁律（从友商血泪中学来的底线，全案不可违背）

1. **原文永不改写**（mempalace：Never summarize, never paraphrase）——流水簿只追加。一切蒸馏发生在别的簿子，原文是唯一真相。
2. **归档永不删除**（N.E.K.O / MaiBot 共识）——被否定的记忆进 `archived` 状态而不是消失，可审计、可恢复、可解释"她为什么记错"。
3. **手动永不覆盖**（Lumi_Nox 铁律）——用户手填的事实 `source=manual`，LLM 永远无权修改。机器会错，人写的不许错。

加一条 OpenGal 自己的：

4. **记忆永不阻塞聊天**——提取/裁决/巩固全部后台化，任何一步 LLM 失败都静默降级，宁可这次没记住，不能这次聊不了。

## 2. 三本簿子的职责与 schema

### 2.1 流水簿（已实现）

`data/chat_history/<角色>.json`——按角色分的全量会话原文（含多模态消息）。

- **职责**：唯一真相、审计、未来"翻旧账"的检索语料。**永不直接注入模型**（见 4.3 近窗护栏）。
- **写入**：随聊天防抖落盘（已实现），append-only 语义。

### 2.2 心记簿——属性事实

`data/memory/<角色>/facts.json`——关于用户/角色/关系的**原子属性**，干燥、结构化。

```jsonc
{
  "id": "f_1724xxxx_ab12",            // 时间戳+hash，幂等
  "text": "用户的生日是 6 月 12 日",
  "entity": "user",                    // user | character | relationship
  "importance": 8,                     // 1-10，LLM 按 rubric 打分
  "confidence": 1.0,                   // 用户明确说=1.0，LLM 推断=0.5
  "source": "user_statement",          // user_statement | llm_inferred | manual
  "created_at": "2026-08-26T10:00:00Z",
  "last_confirmed_at": "2026-08-26T10:00:00Z",  // 再被提及时刷新，参与衰减
  "status": "active",                  // active | archived
  "evidence": { "reinforce": 2, "negate": 0 }   // N.E.K.O 式证据计数
}
```

**记什么**：生日、姓名、身份、稳定偏好、习惯、关系性质。**不记什么**：临时情绪、一次性安排（那是物语簿的事）、闲聊。

### 2.3 物语簿——事件与约定（OpenGal 原创，友商没有的一层）

`data/memory/<角色>/story.json`——**叙事化**的情节记忆，galgame 伴侣的记忆核心：

```jsonc
{
  "id": "s_1724xxxx_cd34",
  "kind": "promise",                   // event | promise | milestone | joke
  "text": "考试挂科那晚，陪用户聊到十二点",   // 叙事短句，≤60字
  "occurred_at": "2026-08-20T21:30:00Z",     // 绝对时间存盘
  "due_at": null,                      // promise 专用：约定到期时间
  "fulfilled": false,                  // promise 专用：是否已兑现
  "importance": 7,
  "status": "active",
  "created_at": "..."
}
```

四种 kind 的语义：

| kind | 是什么 | 例 | 生命周期 |
|---|---|---|---|
| `event` | 共同经历的事件 | "第一次视频通话聊了三小时" | 衰减归档 |
| `promise` | **约定**（galgame 核心意象） | "约好寒假一起看樱花" | 未兑现的**常驻注入**，到期自动浮到最前；兑现后转 fulfilled |
| `milestone` | 关系里程碑 | "互换了名字的含义" | 高权重，衰减慢 |
| `joke` | 梗 / 共同笑点 | "薯条蘸冰淇淋事件" | 长衰减——旧梗是亲密感的证据 |

**为什么单独立一层**：N.E.K.O 的 reflection 接近但面向抽象人格修正；mempalace 逐字但不分重要度。对伴侣应用，"我们经历过什么"比"你是什么属性"更接近记忆的体验本质——用户问"还记得吗"时，问的几乎都是物语。

### 2.4 数据布局（全部在便携 data 根下，装哪放哪）

```
<安装目录>/data/
├── opengal-config.json
├── chat_history/<角色>.json      # 流水簿
└── memory/<角色>/
    ├── facts.json                # 心记簿
    └── story.json                # 物语簿
```

## 3. 写路径：回想（后台，模型只出候选，系统裁决）

### 3.1 触发（攒批，不实时）

| 触发器 | 条件 | 来源 |
|---|---|---|
| 攒批 | 该角色新增 8 个用户轮 | N.E.K.O 攒批思想 |
| 空闲 | 距上次用户输入 5 分钟 | 同上 |
| 收档 | 切角色 / 退出应用 | Lumi_Nox 下播后蒸馏 |
| 手动 | 记忆管理页"立即回想"按钮 | — |

### 3.2 提取（一次 LLM 调用，便宜档模型）

输入=时间窗内的对话；输出=facts 候选 + story 候选。**门禁**（Lumi_Nox 三问 + N.E.K.O rubric 的融合，这是全案质量上限所在）：

```
对每条候选过三关，任何一关不过就丢弃：
  稳定性：一个月后它还成立吗？
  可识别性：它能帮你更懂这个人 / 这段关系吗？
  有依据：对话里明确说了，还是你在猜？

每个候选必须给出 reason；想不出理由的候选直接不输出。
facts 打 importance（1-10：姓名/生日/明确"记住这个"=10；强偏好=7；一般习惯=4）。
promise 单独标记：对话里出现承诺/约定时才生成，带 due_at（能推断就带，推断不出为 null）。
confidence：用户明确陈述=1.0，你推断的=0.5。
严格输出 JSON，不要任何额外文字。
```

### 3.3 裁决（入库前的防污染闸）

新候选 vs 现有 active 集合：

- **高相似** → 不新增；旧条 `last_confirmed_at` 刷新、`evidence.reinforce +1`
- **疑似矛盾**（如生日 6 月 vs 8 月）→ 一次轻量 LLM 判 `reinforces | negates`；negates 则旧条 `archived`、新条入库
- **`source=manual`** → 跳过一切裁决（铁律 3）
- 相似度判定：小规模用关键词/子串（Lumi_Nox 证明够用）；条目过千再升向量（不预支复杂度）

### 3.4 夜间回想（巩固，低频后台循环）

- **衰减重算**：`score = importance × confidence × 0.5^(距 last_confirmed 天数 / 30)`；state 型事实（"在准备考试"）30 天未再确认自动归档——pattern 永存、state 会过期（N.E.K.O temporal_scope）
- **近义合并**：多条相关旧事实合成一条概括，原始条目归档
- **约定巡检**：未兑现 promise 临近 due_at → 注入时置顶 + 标记"该提起了"

## 4. 读路径：回想窗（每轮装配，预算死死压住）

发给模型的上下文由四段装配（[llmWorker](../src/renderer/src/features/pipeline/llmWorker.ts) 的 `messagesForLLM` 构建处）：

```
[1] 角色卡 system prompt          常驻（persona 不进任何记忆池——N.E.K.O 教训：常驻的别再检索）
[2] 记忆块（≤600 token）
    心记簿 top-K（score 排序，K≤12，单条≤60字）
      按 entity 分区渲染：关于用户 / 关于我们
    物语簿：未兑现 promise 全带（置顶）；event/milestone/joke 按 score 取 M≤6
    尾部护栏一行："以上是过往记忆，可能过时，以用户当前所说的为准"（防旧梗绑架）
[3] 近窗对话（滑动窗口，最近 20 轮原文）
[4]（P3）recall 工具：模型自主按需查流水簿原文，找回逐字细节
```

### 4.1 为什么 1M 上下文 + 多模态也必须做记忆

这是本方案成立性的正面回答——窗口大≠不需要记忆：

1. **成本线性增长**：每轮带全量历史，一年聊天每轮都是几十万 token 的真金白银，多模态（图片）token 更贵
2. **中间遗忘**：长上下文的召回质量随长度衰减，重要信息淹没在噪声里；记忆块把最重要的东西钉在注意力前排
3. **窗口终有边界**：流水簿无限增长，总有超窗的一天；近窗+记忆块让窗口需求恒定
4. **记忆≠日志**：能检索到原文（P3）和"她想得起来"（P1 注入）是两种体验，前者大上下文给不了

### 4.2 注入形态（物语驱动的演出，OpenGal 特色方向）

记忆块不是干巴巴的列表拼接。渲染成角色的"内心备忘"：

```
【你记得的事】
关于他：生日 6 月 12 日；最近在准备 CP 考试
你们的约定：寒假一起看樱花（还没兑现——也许该提起了）
你们的经历：考试挂科那晚陪聊到十二点；薯条蘸冰淇淋事件
```

后续可给物语条目带 emotion 标签，注入时驱动 Live2D 表情——"想起约定"本身成为一次演出。

### 4.3 近窗护栏（对现有代码的最小侵入改造）

`runTurn` 里 `...history` 改为 `...history.slice(-40)`（20 轮 = 40 条消息），超窗部分**只存在于流水簿**，由记忆块保证其要点不失忆。护栏与记忆块必须同期上线——只有护栏没有记忆 = 患了失忆症。

## 5. 与友商的对照（学到了什么，扔掉了什么）

| 学来的 | 来源 | 用在哪 |
|---|---|---|
| 三关自检 + 强制 reason | Lumi_Nox | 3.2 提取门禁 |
| importance rubric + confidence 双分 | N.E.K.O | 心记簿 schema |
| 证据计数 / archive 不删除 | N.E.K.O + MaiBot | 3.3 裁决、夜间回想 |
| 攒批提取（非每轮） | N.E.K.O + Lumi_Nox | 3.1 触发 |
| temporal_scope：pattern 永存 / state 过期 | N.E.K.O | 夜间回想 |
| persona 常驻不进检索池 | N.E.K.O | 4.0 装配 [1] |
| 预算推导注释（每个常量写为什么） | N.E.K.O | 回想窗全部预算 |
| verbatim 原文 + 索引只当 boost | mempalace | 流水簿 + 未来 P3 检索 |
| 关键词够用就别上向量 | Lumi_Nox | 3.3 裁决 |
| **反面教材**：infer=False 无门禁 | RachelForster | 引以为戒，提取全系统主导 |
| **反面教材**：建了表不实现 | airi | 每期交付必须端到端可用 |

**扔掉的**：向量库（规模不到）、记忆图/PPR（过度工程）、两阶段信号流水线（N.E.K.O 太重，先单阶段+裁决）、LLM 自由读写记忆（失控之源）。

**OpenGal 原创的**：物语簿（叙事+约定+梗为一等公民）、约定调度（due_at 驱动注入置顶）、注入即演出（记忆带 emotion 的方向）、近窗+记忆块一体化装配。

## 6. 落地计划

| 期 | 内容 | 交付物 |
|---|---|---|
| **P0** | 流水簿（会话持久化）+ 便携数据目录 | 已完成 |
| **P1** | 心记簿 + 物语簿 + 提取门禁 + 裁决 + 回想窗注入 + 近窗护栏 | 端到端最小闭环：聊天→后台提取→注入→角色"记得" |
| **P2** | 夜间回想（衰减/合并/约定巡检）+ 记忆管理 UI（查看/编辑/手动添加/立即回想） | 记忆可运营 |
| **P3** | recall 工具（按需查流水簿原文，混合检索 boost 不 gate） | 翻旧账 |

**P1 具体改动点**：
- `src/main/services/memoryStore.ts`：facts/story 薄存储（仿 chatHistory.ts，原子写）

- `src/renderer/src/features/memory/`（前端）：提取触发器（轮次计数+空闲计时+收档钩子）、提取调用（复用 `llm.chat` 便宜档 override）、裁决
- `buildSystemPrompt`（shared/roleCard.ts）接受记忆块参数；`llmWorker.runTurn` 装配 + 近窗 slice
